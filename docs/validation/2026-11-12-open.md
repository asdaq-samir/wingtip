## How the final pass can run faster

- validate-wave.sh runs every changed spec in one Playwright call; under
  CI's 30-minute `globalTimeout` that cannot finish for a wave this size.
  Batches of about 15 spec files each, one after another, fit.
- A web fix can be checked against the wave's stack without an image
  rebuild: a `vite build --watch` of the worktree (VITE_PUBLISH_DIR=dist,
  the e2e modules volume as node_modules) and the wave gateway re-created
  with `apps/web/dist` mounted at `/app/static/app`, as the web-dev
  profile does.
- The shared repository had been made shallow (its only root was main's
  tip, 9eea5ff1a), so validate-wave found no merge base and would have run
  no changed spec. `git fetch --unshallow origin` mended it; the guard
  that refuses a shallow fetch did not stop whatever did it.
- The guard (.claude/hooks/guard.py) counts a worktree on `claude/val`
  as code in flight and refuses every test in it: only `val-*`, `*-val`
  and `validate-*` are exempt. This pass ran on a local `claude/val-wave`
  for that reason; name the next pass's branch that way.
