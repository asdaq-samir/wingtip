# wingtip's own runtime dependencies: the one place they are listed, and the
# one place each is pinned. Every image that runs wingtip installs this file
# (planner, the retrain and charts jobs, ml), and so
# does the test suite, each through a `-r` line in its own requirements
# file -- which then lists only what that image needs on top.
#
# It used to be the other way round: each image repeated wingtip's imports,
# with a comment tracing the import chain, and a new import in wingtip was a
# new line in six files. On 2026-09-22 wingtip.geo moved to PROJ and only
# planner's file was updated; both agents and both pipeline
# stages then failed on import, and nothing showed it until they were
# restarted.
#
# A new third-party import in services/planner/wingtip belongs here -- or in
# requirements-charts.txt if only wingtip.charts/wingtip.chartvision need it.
# The CI build job imports what each service imports inside its built
# image, so a missing line fails there rather than on a restart.
#
# Pinned to what python:3.15-slim resolves; the pins move on in each
# wave's end pass, with Dependabot's alerts flagging an advisory between them.
numpy==2.5.4        # wingtip.geo, wingtip.ml_features, wingtip.osm, wingtip.weather
pandas==3.1.1       # wingtip.airports, wingtip.faa_data, wingtip.ml_features, wingtip.pipeline
requests==2.34.2    # every external source (wingtip.outside, wingtip.retry)
urllib3==2.8.0      # wingtip.outside's Retry (retry_after_max, backoff_jitter); requests' own pin is only >=1.26
cachetools==8.0.0   # wingtip.sua's day cache of special-use airspace; planner's own caches
tenacity==9.2.1     # wingtip.retry: exponential back-off with jitter around a whole fetch-and-read
APScheduler==3.11.3 # wingtip.schedule: every service's periodic work (the planner's checks, weather's fetches, ingest's beat, crash leads)
pyarrow==26.0.1     # wingtip.faa_data's Parquet cache of the obstacle table; the pipeline's feature store
shapely==2.2.0      # wingtip.airspace polygons, wingtip.weather's hazards, wingtip.osm's representative points
pyshp==3.1.8        # wingtip.airspace reads the FAA Class Airspace shapefile
pyproj==3.8.0       # wingtip.geo -- PROJ's distance/azimuth, scalar and vectorised over a whole corridor
pydantic==2.14.3    # pinned once here for planner's FastAPI and its schemas
pydantic-settings==2.16.2   # wingtip.config's Settings -- every environment variable wingtip and the planner read
scipy==1.18.1       # wingtip.geo's cluster_points KD-tree (imported at wingtip.geo's module level)
pygeomag==1.1.0     # the oracle services/planner/tests_wingtip/test_flight_rules.py holds the engine's WMM-2025 (wingtip.magnetic) to
tzfpy==2.1.2        # wingtip.time_zone: a field's IANA time zone from its position, for its NOTAMs' local times
opentelemetry-sdk==1.45.2                           # wingtip.tracing: spans, where OTEL_EXPORTER_OTLP_ENDPOINT is set (imported only then)
opentelemetry-exporter-otlp-proto-http==1.45.2      # wingtip.tracing: sent over OTLP/HTTP (Jaeger's 4318)
opentelemetry-instrumentation-requests==0.66b2      # wingtip.tracing: a span, and the traceparent, on each source asked
opentelemetry-instrumentation-threading==0.66b2     # wingtip.tracing: the trace carried into threads and pools
